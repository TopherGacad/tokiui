# Installation

tokiui is a copy-paste component library. The CLI adds component source files directly into your project — there is no npm package to version-pin and no theme provider to wrap your app in.

**Requirements:** React 18+, TypeScript, Node.js 18+, Tailwind CSS v4.

## Next.js

### 1. Create the project

When the wizard asks about Tailwind CSS, **choose No** — tokiui will configure it.

```bash
npx create-next-app@latest my-app --typescript --app
cd my-app
```

### 2. Initialize tokiui

```bash
npx @tokiui/cli init
```

The CLI asks three questions — component directory, utility directory, and globals.css path — then handles everything automatically:

- Installs `@tokiui/ui`, `tailwindcss`, `@tailwindcss/postcss`, `clsx`, `tailwind-merge`
- Writes the `cn()` helper to your lib directory
- Creates `postcss.config.mjs`
- Sets up `globals.css` so tokiui owns the theme — on a fresh create-next-app it replaces the starter theme (saving a `globals.css.bak` backup)
- Adds the `@/*` path alias to `tsconfig.json`
- Creates `tokiui.json` to save your choices for future `add` commands

<Callout>
On a fresh create-next-app, `init` **replaces** the starter theme in `globals.css` — the `@theme inline` / `prefers-color-scheme` block create-next-app ships — with tokiui's, saving your original to `globals.css.bak`. This is deliberate: that starter theme defines its own `--background`/`--foreground` and would otherwise override tokiui's tokens (the classic symptom is white cards on a dark OS).
</Callout>

<Callout type="warning">
tokiui requires **Tailwind CSS v4**. If a `tailwind.config.ts` / `tailwind.config.js` file exists (the hallmark of v3), `init` prints a warning but keeps going — tokiui's tokens won't resolve correctly until you [migrate to v4](https://tailwindcss.com/docs/upgrade-guide) and remove the config file.
</Callout>

### 3. Add a component

```bash
npx @tokiui/cli add button
```

Run without an argument to pick from an interactive list:

```bash
npx @tokiui/cli add
```

### 4. Import and use

```tsx
import { Button } from '@/components/ui/button'

export default function Page() {
  return <Button>Click me</Button>
}
```

Start the dev server:

```bash
npm run dev
```

## Vite

### 1. Create the project

```bash
npm create vite@latest my-app -- --template react-ts
cd my-app
npm install
```

### 2. Initialize tokiui

```bash
npx @tokiui/cli init
```

The CLI asks three questions — component directory, utility directory, and globals.css path. Point the CSS path to `src/index.css` (Vite's default global stylesheet).

It then handles everything automatically:

- Installs `@tokiui/ui`, `tailwindcss`, `@tailwindcss/postcss`, `clsx`, `tailwind-merge`
- Writes the `cn()` helper to your lib directory
- Creates `postcss.config.mjs`
- Prepends the required imports to `src/index.css`
- Adds the `@/*` path alias to `tsconfig.json`
- Creates `tokiui.json` to save your choices for future `add` commands

<Callout>
Vite scaffolds a `src/index.css` with some default styles. The CLI prepends the Tailwind imports at the top — the existing styles remain. You can remove them once you're set up.
</Callout>

### 3. Add a component

```bash
npx @tokiui/cli add button
```

### 4. Import and use

```tsx
import { Button } from '@/components/ui/button'

export default function App() {
  return <Button>Click me</Button>
}
```

Start the dev server:

```bash
npm run dev
```

## Remix

### 1. Create the project

```bash
npx create-remix@latest my-app
cd my-app
```

When prompted, select TypeScript. Remix v2+ uses Vite internally so no additional bundler config is needed.

### 2. Create a global stylesheet

Remix doesn't auto-import a global CSS file, so create one manually:

```bash
touch app/tailwind.css
```

### 3. Initialize tokiui

```bash
npx @tokiui/cli init
```

When the CLI asks for your globals.css path, point it to `app/tailwind.css`. Use `app/components/ui` and `app/lib` for the component and utility directories.

It then handles everything automatically:

- Installs `@tokiui/ui`, `tailwindcss`, `@tailwindcss/postcss`, `clsx`, `tailwind-merge`
- Writes the `cn()` helper to your lib directory
- Creates `postcss.config.mjs`
- Writes the Tailwind + tokiui imports to `app/tailwind.css`
- Adds the `@/*` path alias to `tsconfig.json`
- Creates `tokiui.json` to save your choices for future `add` commands

### 4. Link the stylesheet in your root route

Open `app/root.tsx` and add the stylesheet using Vite's `?url` import:

```tsx
import type { LinksFunction } from '@remix-run/node'
import stylesheet from './tailwind.css?url'

export const links: LinksFunction = () => [
  { rel: 'stylesheet', href: stylesheet },
]
```

### 5. Add a component

```bash
npx @tokiui/cli add button
```

### 6. Import and use

```tsx
import { Button } from '@/components/ui/button'

export default function Index() {
  return <Button>Click me</Button>
}
```

Start the dev server:

```bash
npm run dev
```

## Blocks

Components are single files. **Blocks** are multi-file compositions — a full sidebar, a dashboard shell — that install as a self-contained folder, and when a block defines a route the CLI wires up a ready-to-use page for you.

```bash
npx @tokiui/cli add sidebar-shell
```

This drops the block into `components/blocks/sidebar-shell/` and creates `app/dashboard/page.tsx` (or `src/app/dashboard/page.tsx`) that renders it — so **/dashboard** works immediately, with no importing or wiring:

```text
✔ Added block sidebar-shell
  ✓ ready at /dashboard  (app/dashboard/page.tsx)
```

Blocks pull their primitives from the `@tokiui/ui` you already installed, so there's nothing extra to configure — edit the files under `components/blocks/` to make them yours. Browse what's available in the [Frames gallery](/frames).

## Manual setup

If you prefer to skip the CLI and wire things up yourself:

**Install packages**

```bash
npm install @tokiui/ui tailwindcss @tailwindcss/postcss clsx tailwind-merge
```

**Add to your global CSS file**

```css
@import "tailwindcss";
@import "@tokiui/ui/styles.css";
```

**Create `postcss.config.mjs`**

```js
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
}
```

**Add path alias to `tsconfig.json`**

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

**Add the `cn()` utility to `src/lib/utils.ts`**

```ts
import { clsx, type ClassValue } from 'clsx'
import { twMerge } from 'tailwind-merge'

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

**Create `tokiui.json` at your project root**

```json
{
  "componentsDir": "src/components/ui",
  "libDir": "src/lib",
  "libAlias": "@/lib",
  "style": "default"
}
```

`libAlias` must line up with your `@/*` alias and `libDir` — the CLI rewrites each component's `cn()` import to `${libAlias}/utils`. With a `src/` directory, `@/*` maps to `./src/*`, so drop the `src/` prefix (here `src/lib` → `@/lib`).

Then add components with the CLI:

```bash
npx @tokiui/cli add button
```
