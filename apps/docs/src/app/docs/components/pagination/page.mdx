## Basic

The active page gets `isActive` which applies the filled primary style and `aria-current="page"`. Disable `PaginationPrevious` / `PaginationNext` at the boundaries by adding `pointer-events-none opacity-50` when at the first or last page.

## Using with Next.js

`PaginationLink` supports `asChild` to swap the `<a>` for any routing component.

```tsx
import Link from 'next/link'

<PaginationLink asChild isActive={page === 3}>
  <Link href="/items?page=3">3</Link>
</PaginationLink>

<PaginationPrevious asChild>
  <Link href={`/items?page=${page - 1}`}>Previous</Link>
</PaginationPrevious>
```

## API

### PaginationLink

| Prop | Type | Default | Description |
|---|---|---|---|
| `isActive` | `boolean` | `false` | Marks the current page — applies filled style and `aria-current="page"` |
| `size` | `icon \| default \| sm` | `icon` | `icon` is square (for page numbers), `default` includes text padding (for Previous/Next) |
| `asChild` | `boolean` | `false` | Renders the child element instead of `<a>` |

### PaginationPrevious / PaginationNext

Extend `PaginationLink` with `size="default"`, a chevron icon, and an accessible `aria-label`. All `PaginationLink` props apply.

### PaginationEllipsis

Decorative `···` indicator. `aria-hidden="true"` with a `sr-only` "More pages" label for screen readers.

## Accessibility

- `<nav role="navigation" aria-label="pagination">` wraps the whole control
- Active page link carries `aria-current="page"`
- Previous/Next buttons have explicit `aria-label` values
- Disabled states should set `aria-disabled="true"` on the link (in addition to visual opacity) so screen readers announce them correctly
